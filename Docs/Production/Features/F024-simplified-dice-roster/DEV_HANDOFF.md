# F024 程序交接：30 颗骰子如何接入现有原型

负责人为程序。2026-11-23 已接入，逐颗对照及废弃标记见 [名册](ROSTER.md)。实际入口为 `Assets/Scripts/DiceKingDemo.cs`、`DiceKingDemo.Round.cs`、`DiceKingDemo.MarketSave.cs`。以下保留设计与实现交接时的取舍。首测采用的口径和 Unity 运行结果见 [验证记录](../../../QA/20261123_f024_runtime.md)。

## 一、先分清四种数值

| 数值 | 运行时落点与写入时机 | 验证方法 |
|---|---|---|
| 长期六面 | 以 `Die.Faces` 表示实际长期点数。均匀加点可复用 `AddValueToAllFaces`。保留 `FeedCount` 和累计实际饲料贡献用于转移及详情，六面只加一次。移除 `ApplyFeedMinimum` 的旧托底效果和 `PopulateTooltipEffectiveFaces` 的旧预览叠加。 | 普通骰吃一份初始饲料后，从 1/2/3/4/5/6 变成 2/3/4/5/6/7。保存、读档、打开详情均得到同一面组。 |
| 本手点数与贡献 | `LastValue` 保留自然投出值，`EffectiveValue` 表示本手采用的点数。`Score` 和结算贡献记录承载独立加分。王冠改本手点数。长期增长是否改变尚未结算的位置，按具体效果处理。抢劫须支持已结邻位本手计零。 | 王冠改到最大面后再次开详情，长期六面相同。抢劫后左邻的基础与附加计分全部归零；海盗只拿该邻骰本手投出的点数。邻骰已经产生的金币、喂养和长期成长仍保留。 |
| 货架强化 | 给市场骰保留原面组，分开记录小鬼的整局累计值与吸血的本市场临时值，从同一读口生成展示与吞噬的有效六面。当前 `ApplyCurrentTavernMinimum` 会改写商品，而 `MakeRandomMarketOffer` 和 `BuildMarketOffers` 都有调用，改成加法时只能应用一次。 | 用同一货架分别检查首次生成、重复查看、购买、刷新、定向换货和吞噬。临时加成在购买离架与吞噬转移上的差别见第三节。 |
| 价格 | 统一使用 `CurrentOfferPrice` 出报价、检查资格和扣款。`SellPrice(Die)` 读取实例可回收金额，壳价按规定独立累加。旧 `FormulaSellPrice` 把饲料、壳价与面组成长合并估值后再按买卖比例折算，不能直接表达新规则。 | 海盗半价购买后按约定同价卖出；宿主挂两枚售价为 1 的基础龟后，可回收金额累计 +2。吞噬者的卖价在吞噬前后相同，即使吞噬抬高六面也不能通过卖价公式隐式增值。 |

**已确认：吸附与吞噬均按面序逐面对位相加。** 在消费来源前锁定双方六面，第一个面加第一个面，依次直到第六个面。例如六个 1 吸收 1/2/3/4/5/6 后得到 2/3/4/5/6/7。现有 `DevourTransferValue` 返回向下取整并保底 1 的面均值，接入时以成组六面相加替换此标量路径。同一来源只消耗一次。吞噬对价不转移，吸附同时保留壳类型、来源和可回收金额。

## 二、回合、分数与重复触发

**已确认每实际投一手就算一回合。** 失败扣命后的同关续投是新回合，按回合触发的效果再次发动。恢复到等待投掷界面本身不触发效果。下表为建议的阶段切点和同阶段执行顺序。

| 顺序 | 接入点 | 行为 |
|---|---|---|
| 1. 回合开始 | `BeginShakeRoll` 通过投掷资格检查后 | 先锁定效果清单，按袋序、同宿主按附着先后处理金钱龟、小小龟、倍数龟效果。回溯仅扩大本阶段效果的执行次数。 |
| 2. 投出结果 | `LockCurrentRollResults` 在全体投出与首次预览之间 | 王冠从己方实体中随机抽取最多两颗不同目标，写入其本手最大面。存在多枚王冠时每枚各抽自己的目标。一次投掷只做一次随机选择。 |
| 3. 逐槽结算 | `BeginSettle → ScoreDice` | 继续按实体实例编号从左到右取主根。同一槽的本体、附着效果和局部响应完成后记入分数。二重唱重做约定的结算效果，基础点数仅记一次。 |
| 4. 结算后／回合结束 | 完整结算数据确定后、通关或扣命分支之前 | 光牙、母猪按袋序执行。附魔师仅重复合资格的回合结束效果。失败手也走收尾；已经确定的本手分数不因收尾成长回写。 |
| 5. 显示／转场 | `PrepareSettlementDisplayEvents`、`ApplyCommittedSettlementSnapshot`、`CompleteScoreReveal` | 演出读取提交的贡献与目标；过关收入、扣命、跳转与保存各执行一次。加速、跳过、悬浮预览及重复绘制没有规则副作用。 |

复用 `GameplayChainContext`、`FamilySettlementContext` 和已有 `[CHAIN]` 日志。建议对每次根效果保存来源实例、阶段、重复序号，先取合资格实体／壳层快照，再按槽位和附着先后处理。每个正当执行产生的喂养、吞噬、入账等事实各广播一次；重复器、已复制效果与派生响应不得再申请重复同一阶段。建议同一阶段有多颗同类重复器时，总执行数固定为两次。法术回声如仍在旧袋中，沿用其“复制不能再次复制”标记。建议二重唱覆盖本体结算效果和首领龟、领队龟的宿主结算效果。首领壳可再次向其它各带壳骰分发它们各自的附加分，领队壳可再生成一枚基础龟，新生成的基础龟自身没有结算能力。金钱龟等回合开始能力归回溯处理，基础分、统一金币结账和关卡胜负各提交一次。

## 三、30 颗骰子的开发落点

| 家族 | 新规则如何写入 |
|---|---|
| 猪 | **喂养者**在本槽建议给相邻有效位置各发一份。**肉猪**在 `GrantFeed` 接收时将一份折为两份，两份 × 获得时品质即为六面实际增量，只发布一次接收事件。**转移猪**复用 `SellSelectedMarketDie` 的离袋前快照及原槽位响应，从剩余实体中随机选一颗继承已有饲料。建议把历史份数与实际点值作为同一笔喂养交给接收者，品质变更后仍用历史实际价值；肉猪可放大整笔，其他贪吃猪可响应一次。由统一受喂入口入账，避免直接加面后再喂第二次。**母猪**在回合结束给除本体外每颗实体一份。**贪吃猪**仅响应另一颗猪获得饲料，每次事件得一份，贪吃衍生喂养不再广播给贪吃猪。**批发商**移到卖出自身的虚拟槽位响应，使每份饲料的基础加值 +1；建议仅影响此后新发放的饲料。旧按份增加卖价的分支从新饲料路径移出。 |
| 龟 | 沿用 `BeginMarketLeaveEffects → ResolveF018TurtleAbsorption` 的离场顺序与既有右邻非龟宿主资格。新增类型并更新可吸附名单。实体离袋时把来源基础点转给宿主并保存壳。**金钱龟**由每回合的壳效果调用 `AddGoldIncome(1,…)`。**小小龟**给宿主长期六面各 +1。**倍数龟**取宿主当前长期最大面 ×2；建议将执行前全部并列最高面各翻倍一次。**首领龟**已确认在其宿主结算时，给其它每颗带壳骰各加本手分，每层壳为该骰贡献 1 分。其它两骰各有 2 壳和 1 壳，则两骰分别 +2、+1，首领宿主自身 +0。按受益骰实例记录分数：对已结槽修正其已提交贡献与本手合计，对待结槽登记附加分，结到该槽时一次计入，所有目标均不重播本体效果。建议计入领队生成的基础龟；如受益骰已被抢劫标记本手计零，最终贡献仍按抢劫规则处理。**领队龟**在宿主结算时直接挂一枚**基础龟**，记录六个 1、售价 1 的来源；基础龟无后续能力。它不占新的袋槽，不重新扫描领队，不能沿用无卖价的旧 `BasicShell`。基础龟实体与生成的壳应共用点数和卖价口径。 |
| 恶魔 | **小鬼骰子**已确认每次入市只提升骰子货架的基础六面，各 +1，整局累计。将入市累加放在 `EnterMarket` 的首次进店事务中，当前货架与之后刷新、定向换货等生成的骰商品继承累计值；己方袋内骰不因进店增点。刷新只读取既有累计值。**蝠魔骰子**在 `ResolveMarketLeaveEffectForDie` 让其它恶魔依袋序各吞一颗合资格商品，执行前重查剩余货架，食物耗尽即停。**吸血骰子**随本市场每次成功买骰使未售及随后生成的骰子商品六面临时 +2；法术、改造道具、刷新和吞噬不能充当买骰。建议买走的普通骰去掉吸血临时层，当场吞噬按货架有效面取值。离场吞噬完成后才释放本市场临时层。**深渊骰子**只在入店生成 1–3 个祭品，六面均为 1，可读货架强化，仅恶魔能吞；建议每店合计一次抽 1–3 枚，优先占骰子格，多颗深渊不叠加。消耗候选先取祭品；建议保留满袋可花钱奉献、无恶魔不可奉献的专门分支，普通付费刷新不补祭品。**吞噬骰子**每颗每次成功吞噬入账 1。**始祖魔骰子**在成功购买恶魔后从剩余合资格骰商品随机取一颗，由响应的始祖魔吞噬。购买对象与货架食物分别移出一次。把 `ResolveDevour` 的受益者改为显式恶魔实例，替换当前自动寻找“全袋最低面”的实现。 |
| 海盗 | **哨兵海盗**通过 `CurrentMarketRefreshNetCost` 每颗减 1，多颗相加，净负数经 `AddGoldIncome` 返利。建议沿用章节基础费及 `market_refresh_cost_step` 逐次递增曲线，“固定”只指每颗哨兵恒减 1；若要取消递增，应作为独立经济调整确认。**抢劫海盗**已确认拿走左右邻骰本手投出的点数，两邻本手计零，所得均摊到海盗自己的长期六面，每次抢劫共得 3 金。分别记录“可洗劫的本手点数”和“本手贡献”：左邻若已结，撤回其全部计分，右邻若尚未结，将计分标记为零。两邻单骰附加分（含龟壳加分）随之清零，只有投出的点数进入均摊；喂养、成长、金币等独立效果照常发生。建议余数按稳定面序分发。负点如何处理、二重唱第二次遇到空劫是否再发 3 金仍待确认。**财宝海盗**继续监听正数真实入账，每次事件随机己方一颗六面 +1，入账 3 金也是一次。**海贼王**本槽读取当时钱包，按整除 3 增加自身基础点数，不扣金币。**海盗头领**建议每个市场共一次海盗半价额度，持有头领时成功购买才消费，刷新货架不重置额度。中途首次买到头领时，头领本单按购买前的报价成交；若本店额度尚未使用，入袋后首次成功买海盗可用半价。**人口海盗**每主动售出两颗实体给 1 金，建议按在场的人口海盗实例跨市场累计，余数 1 写入实例存档；删除旧招募基础骰效果，出售挂有龟壳的宿主计一次交易。全家族买卖同价建议按购入实付金额保存实例价格，另加之后吸附的壳价。 |
| 中立 | **光牙骰子**建议回合末统计袋中四个主体家族的不同数量，将 2 × 数量加到每颗己方实体的长期六面，包括光牙自己；壳不另提供身份。**王冠骰子**改在投后调整两颗点数，清掉旧均值加分路径。**附魔师骰子**重复回合末，**回溯骰子**重复回合开始，**二重唱骰子**重复结算效果，见第二节。**税务骰子**已确认对每件骰子商品的购买报价各减 1。三格骰子标价为 3、4、5 时，持有一枚税务骰子后的报价分别是 2、3、4。建议与头领并存时先逐件减价、再半价向下取整，最低为 0；将折扣顺序、底价与奇数价格写入报价测试。 |

## 四、供给、旧档和验收顺序

1. **名册和供给。** 依 [名册](ROSTER.md) 维护当前类型、家族、系统用途和废弃状态。`DieType` 原枚举值保留，新增键追加。核对 `dice_type_config.csv`、`dice_market_config.csv`、`keyword_binding_config.csv`、`keyword_glossary_config.csv`、`global.csv` 及代码回退。基础龟建议兼有普通供给与领队生成的取得方式，需同时检验。普通权重、保底、专池、随机测试、无候选回退 `FallbackMarketOfferType`、法术定向换货 `MakeFamilyRestockOffer` 都交给同一资格判断。固定六个 1 的基础龟和祭品要跳过随机面模板。普通开局基础骰沿用开局入口，祭品仅从专有入口生成。废弃键可以解析历史数据，不能作为新局选项。
2. **市场事务。** `EnterMarket` 区分首次进店与重建显示，`BuildMarketOffers(false/true)` 区分首次供给与刷新。原代码逻辑生成三个货格、深渊固定占第 0 格，即使界面能分页也须单独处理 1–3 祭品与普通货架容量。将祭品资格判定、占位与消费放在规则层，法术换货、刷新和手动购买都遵守同一约束。买入先检验资金／容量，再扣实价并移出商品，提交入袋后才广播买骰；对售出、实际吞噬、离场各用自己的事件。事务完成后保存。未成交、空位、无宿主／无恶魔均不给入账或购买次数。
3. **存档。** 当前 `CurrentSaveVersion = 14`，`LoadMenuState` 对低于当前版本的档位会调用 `ClearSave`，`ContinueGameFlow` 通常经 `StartEncounter` 恢复。当前未保存原市场货架和逐件实付价。切换前由策划确定 v14 兼容策略；先读取并保留原局样本，再决定是否迁移。迁移只映射名册明确兼容的实例与壳；旧 `FeedValue` 是托底值，不能不加区分地再对已增长的六面加一次。解析器 `TryParseDieType` 同时接受字符串和整数，两条都须验证新局资格。低版、未来版、未知键、旧附壳及全袋废弃分别有测试样本，不能让市场途径回流旧骰。
4. **新档稳定点。** 在 `SaveRun`、`SerializeDice`、`LoadRunCollection`、附壳序列化与 `Die.Clone` 对齐长期六面、饲料账、壳价及类型、海盗实付价、售卖进度；另按整局保存小鬼累计的货架基础加值。若恢复原市场，还需保存市场身份／空格、原商品与强化层、已使用的半价及刷新次数，并按恢复分支原样装回；不得当作再次入店。若沿用原小关检查点，明示该语义并以整笔交易的一致快照保存。回放采用已提交的目标与数值，恢复已完成阶段不得重发随机事件。
5. **验证入口。** 先在脚本层用固定面组、固定袋序、指定货架复现 [验收表](ACCEPTANCE.md)；再走 `WabishHeadlessPlaytestRunner.RunFromCommandLine` 的正式投掷、购买、出售、刷新与离场入口，用固定种子比对队列和金钱。最后在 Unity 检查两种市场、继续游戏、扣命续投与快慢演出。倍数龟的长期倍增应以 40 关和双触发组合核查 `int` 面组、合计、得分与存档溢出；数值上限属于策划参数，避免静默回绕。只有这些样本实际通过后才更新主文档中的运行时快照。

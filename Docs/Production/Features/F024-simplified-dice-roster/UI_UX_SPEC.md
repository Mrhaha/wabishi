# F024 界面体验交接

**负责角色**　界面体验、程序。玩家要能在购买前看懂这颗骰影响谁、在哪一步生效，以及收益会留在哪个对象上。具体规则与旧名映射以本包 `FEATURE_BRIEF.md`、`ROSTER.md` 为准。

## 玩家可见内容

| 界面与时点 | 玩家操作 | 应看见的信息 |
|---|---|---|
| 准备投骰 | 悬浮查看，拖动排序，取消拖动或确认投掷 | 家族壳、类型芯和现有六槽顺序。详情显示新名称、触发时点、目标与六个基础面。可通过调位预测喂养者和抢劫海盗的左右邻骰。 |
| 投出至结算 | 观察王冠选中的骰、逐槽结算和结束阶段 | 王冠只标记受影响的实例并显示调整后的当前点。结算短反馈用动词和数量表示，如“喂 1 份”“得 3 金”。海贼王的成长显示在长期六面，本手数字保持锁定值。 |
| 市场购物 | 查看货架与钱包，点选买入、卖出或刷新 | 一枚税务骰使每件骰子商品的报价各减 1 金，购买键与扣款显示同一笔实付。按海盗头领每次入市发放半价的建议，优惠用过后立即重算，同店刷新保留已用状态。刷新显示“费用”“免费”或“可返”及相应金币。祭品悬浮说明来源及合法去向。 |
| 离开市场 | 调位并查看离场预览，点击离开 | 复用现有离场锁定与顺序反馈。吸附与吞噬显示来源和目标，详情按对应面呈现相加前后的六面。吸附同时显示累计卖价，吞噬显示吞噬者原有卖价。若可用货架已被上一颗恶魔吃掉，以实际结果为准。 |
| 同回合的多个触发及失败续投 | 在已有短反馈和详情中查看结果 | 一手投掷算一回合。失败后的续投重新显示本回合的开始、结算和结束收益。正常和额外发动在可追踪的反馈中有次数区别。同一格连续两次投喂可合并显示“喂 2 次”。底层保留两次事件的明细。 |

首领龟的规则文字写为“宿主结算时，其他骰子每带一只龟，自身本手加 1 分”。在每颗受益骰的计分明细显示该骰所得，包括已经结算的左侧骰。海盗同价说明应写明折扣和壳层是否计入。特殊价格和点数随状态变化时，以规则层计算结果刷新。

## 悬浮详情

| 对象 | 优先显示 | 需要辨明的差异 |
|---|---|---|
| 饲料持有人与批发商 | 当前饲料份数、饲料贡献的基础点数、下一份的加值 | 与六面实际增量对得上。旧「最低点托底」「喂养涨卖价」提示随规则切换退场。 |
| 宿主 | 身上的龟种类和层数、累计回收金额、实际六面 | 同种壳多枚时汇总，其作用仍可查。基础龟与默认开局的基础骰名称分明。 |
| 市场骰、祭品与恶魔 | 可用于吞噬的六面、小鬼的整局货架加值、吸血骰的本店临时加值 | 每次带小鬼进店，货架各面加值累计，新刷商品继承当前累计值。袋中骰的详情维持其原面组。吸血骰的临时加值单列，离场后清除其临时提示。是否保留已结算的临时加成转移按正式规则显示。 |
| 海盗 | 货架最终价、本人回收价、下次刷新价及相关限次 | 抢劫时左右邻骰本手骰点显示归零。左邻已入分则同步校正分数，已发放的金币、饲料照常。海盗详情显示所得均摊后的长期六面，抢劫的 3 金单列。若邻骰另有独立加分，其处置按策划裁定显示，抢到的数值只包含邻骰本手骰点。 |
| 中立 | 明确写“投出后”“结算”“回合开始”或“回合结束” | 光牙标不同主体家族数。三个重复器标出复制的阶段，避免将整次计分或交易误读为二次执行。 |

## 接入与验收

- 程序检查 `Assets/Scripts/DiceKingDemo.cs` 的 `BuildDiceTooltipViewModel`、`TooltipTriggerLabel`、市场买卖及刷新报价和离场预览。类型规则、关键词解释、绑定分别检查 `Assets/Resources/Data/dice_type_config.csv`、`keyword_glossary_config.csv`、`keyword_binding_config.csv`。
- 复用已有市场按钮与准备区拖拽。取消拖动恢复原顺序。取消或失败动作保留饲料、壳、购物次数、钱包与六面。离场反馈锁定期间连续点按不能提交第二笔交易。
- 在 `1280×720` 和 `1920×1080` 各检查市场购买、负费刷新、壳详情、结果调最大值、连续重放以及最长骰名。先核查 LED 缺字和折行，再依 `Docs/UI_ACCEPTANCE_FEEDBACK_WORKFLOW.md` 采集实机截图。
- 本页交付界面规格。界面截图、运行数值比对以及最终文案的批准均留到实现阶段记录。

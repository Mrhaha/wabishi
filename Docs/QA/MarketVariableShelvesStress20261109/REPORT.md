# 关间商店可变数量离线压力测试

日期：2026-11-09

本报告保留第七十五轮常驻全文方案的历史结论。用户在第七十六轮已确认法术常态改为插画与必要文字、全文移至悬停；当前原型与复测结果见 `SPELL_CARD_HOVER_REPORT.md`。旧“两张法术每页”的结论不再限制新图文卡，原指标与截图仍保留供追溯。

关联：`Docs/DesignDialogues/F021-arcade-cabinet-main-menu.md` 第七十五轮。

## 结论

原“三张法术同屏”的美术示意未通过真实字库装入检查。修正为骰子每屏四颗、法术每屏两张后，离线布局与分页原型通过本轮数量矩阵、完整正文、原索引命中和购买留空检查。页面容量不是商品数量上限。

当前 Unity 仍使用固定三格商店，未接入新分区或分页。本轮未启动 Unity Play Mode，也未修改运行时代码、供给配表、经济、骰子效果或存档；本报告不能作为 Unity 功能已完成或正式字体已验收的证明。

## 测试范围与证据

- 原生分辨率：`1280×720`、`1920×1080`。
- 骰子数与法术数分别取 `0 / 1 / 2 / 3 / 4 / 6 / 8 / 12 / 32`，两类交叉组合，每种分辨率八十一组，合计一百六十二组。
- 累计一千一百七十次状态检查，包括起始状态和各类分页遍历；该计数含重复首屏观察，不是一千一百七十个独立场景。
- 十二项跨分辨率交互检查，覆盖四位价格、末页购买、目标选择、交易锁定、换货变类和整批重建。
- 使用现有 `main_game_led_font_map.csv`、`main_game_led_font_styles.csv`、亮度角色表、八张启用法术全文和现有骰子名称。源文件哈希、逐组结果与字宽指标保存在 `metrics.json`。
- 商品图复用现有家族壳和类型芯。浅色键使用项目已有实心字体，发光文本使用现有字形与整数点绘制；没有生成新字库或通过省略正文满足装入。

## 发现并修正的布局问题

### 三张法术并排高度不足

现有 `Compact` 逻辑格高为 `31`，行高为 `35`。三卡候选的正文宽约 `296`，在固定正文安全框 `105` 高中出现以下失败：

| 法术 | 三卡候选所需正文高度 | 安全框 | 结果 |
|---|---:|---:|---|
| 连锁分红 | 136 | 105 | 超出 |
| 回声指令 | 136 | 105 | 超出 |
| 定向换货 | 171 | 105 | 超出 |

定向换货是当前启用法术中最长的正文，共四十九字符。将法术卡改为每页两张、每张宽 `496`、正文宽 `472` 后，八张启用牌最多三行，正文最大高度为 `101`，可装入 `105` 高安全框。

当前修正版法术卡高 `224`，名称、正文、实际价格和购买键分别留框。区头与翻页同一行，不另挤占正文高度。没有退到 `Micro`，没有缩字或删改牌效。

### 四位价格安全框不足

额外边界值 `9999 金` 的真实字宽为 `103`，最初 `100` 宽价格框超出三像素。离线原型已将其扩大为 `104`，与购买键仍保留八像素间隔。初次失败证据保存在 `initial-price-overflow.txt`。

### 分页文案缺字

现有字库未覆盖“页”以及 `‹ / ›`。本轮原型使用现有的 `< / >` 与 `1 / 4` 等数字表示，不临时增加系统字体旁路。正式文案若使用“上一页／下一页”，须先按现有同源流程重建字库。

## 交互检查

| 检查 | 结果 |
|---|---|
| 分页遍历全部真实商品 | 每个预期商品恰好出现一次，无丢失或重复 |
| 末页通过真实按钮购买 | 命中原始货架索引，不按当前屏序号误买 |
| 购买后留空 | 保留原货位、当前页与列表长度，其余商品不挤动 |
| 两类分页 | 各自保持独立页码 |
| 末页选择目标 | 命中原索引，不会因分页变成另一商品；该项仅测试显示原型的命中映射 |
| 交易锁定 | 交易按钮受阻，直接尝试动作也不新增空货位 |
| 法术商品变为骰子 | 保留商品标识与原索引，不新增货架 |
| 整批重建 | 两类页码复位，不沿用失效页码 |

这些交互发生在离线原型，未调用正式 `BuyOffer`、法术事务、经济监听或离场队列。

## 入口修复与回归（2026-11-09）

用户直接打开原 `stress-template.html` 后只见控件，没有画面和数量选项。原因是该文件含未替换的数据与字体占位符，原构建器只生成 `index.html`，没有保护模板地址。

本轮将构建源文件移为 `stress-template.html.in`，原地址改成可用兼容入口，并重新生成完整页面。两侧数量选择现在会立即重建对应批次，不需要额外点击。页面增加早期同步异常、脚本加载失败和异步资源错误提示，避免初始化失败时静默空白。

通过 `check-entry.cjs` 在实际本地文件协议下验证 `index.html` 与 `stress-template.html` 两个地址：各自九个数量选项完整，四／六／八／三十二件选择后立即生效，两类分页独立，末页购买留空和页码稳定，重建恢复商品，原生两档分辨率的点击热区正确，浏览器错误为零。另以故障注入确认缺少数据时能显示明确提示。

原一百六十二组数量组合与十二项交互检查也已重跑通过。入口验证结果为 `entry-checks.json`，修复后完整页面截图为 `entry-fixed.png`。本轮没有修改 Unity 或配表。

## 限制与下一步

- 本轮装入与分页通过，不等于正式字体四门或整套界面验收通过。当前 `Compact` 在 `720p` 使用已登记的一像素核心；非整数压力图正文偏细，保留人工可读性复核。
- 原型使用同源字形和测量，但不是 Unity 逐像素真值。原型对全局起点与灯点偏移统一取整，C# 则先生成行纹理再独立取整起点，`1080p` 半像素起点可能有一像素差异；本原型也未复刻 `DrawClippedTexture` 的裁切。
- 当前八张法术最多三行，正文安全框保留四像素余量。后续新增更长牌效时需要重跑，不能把本结果外推为所有未来文本均可装入。
- 建议后续实现以骰子每屏四颗、法术每屏两张作为待确认候选，保留配置化列表与分页；接入时同步商品绘制和法术目标选择，再做原生双分辨率 Play Mode 回归。
- 本轮没有修改运行时代码、配表、实际商品数量、随机、经济、存档或 `ART_ASSETS.md`。
- Notion 未同步：当前没有可用连接工具。
